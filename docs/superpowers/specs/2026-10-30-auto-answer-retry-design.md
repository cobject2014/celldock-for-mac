# 自动接听失败重试与明确提示

## 目标与范围
修复自动接听一次失败后整通来电不再尝试、错误原因只短暂提示或显示内部错误代码的问题。保留现有延迟设置、只听不开麦、接通后自动录音。不得自动回拨、修改 SIM/固件、开启麦克风权限或结束其他应用。

## 已选方案与取舍
用户选择有限重试：每通最多 3 次，失败后间隔 3 秒；相较只提示由用户手动重试，可恢复短暂故障；相较无限重试，避免重复发接听命令及长期占用接口。

## 行为
- 首次尝试仍使用用户设定的振铃延迟。每次失败后仅在同一通电话仍处于明确的 incoming 状态、无进行中的接听/清理操作时重试。
- 接听结果不明确或进入 recovering 时不得重复发送 ATA；必须先确认仍是原来电。断开、更换模块、接通、来电结束、用户手动接听/拒接或关闭自动接听立即取消旧任务；迟到回调不得影响新来电。
- 语音组件不可用时显示明确阻塞原因，不将其当成已准备好；不通过忽略语音初始化失败来强行接通。模块仍有来电时不运行仅允许空闲状态执行的完整初始化。
- 来电界面持续显示失败原因和重试进度/达到上限的提示，直到成功、通话结束或用户操作；不要只依赖短暂 toast。初始化错误显示本应用已知的可读错误，例如 ADB 控制接口被占用，而非仅 NSError 数字。
- 初始化和自动接听失败记录必要诊断信息（状态、尝试次数、错误原因），避免记录号码、短信或凭据。
- 本次人工恢复先停止当前仅连接目标模块的 adb 服务，再正常重启 CellDock 初始化；产品中不新增自动杀 adb 行为。

## 实现与验证
在现有 Swift 状态门控及 AppState/ModemService 接听回调上做窄范围修改，不新增依赖。以确定性测试覆盖失败后重试、三次上限、取消、迟到回调及跨模块隔离；覆盖可读错误与 UI 状态，运行完整测试并构建验证。真实来电接听/录音验证由用户拨打测试电话配合，不能用单元测试代替硬件验证。
